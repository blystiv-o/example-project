# Нефункціональні вимоги

- Застосунок має швидко відкриватися та реагувати на дії користувача без помітних затримок.
- Дані користувача мають бути захищені від несанкціонованого доступу.
- Інтерфейс має коректно працювати на мобільних, планшетних і десктопних екранах.
- Основні дії мають бути зрозумілими без додаткового навчання.
- Помилки мають оброблятися без втрати введених користувачем даних.
- Застосунок має формувати структуровані логи у форматі JSON; усі записи в межах одного запиту або операції мають містити `trace_id` для наскрізного відстеження та кореляції подій.
- API має записувати логи у NDJSON-файл, визначений змінною `LOG_FILE` (типово `logs/api.log` від кореня проєкту): один JSON-об'єкт на рядок.
- Для HTTP-запитів, які завершилися server error, API має створювати canonical log line з `log_type=canonical`, подією `http.request.completed`, `trace_id`, результатом, тривалістю, HTTP-методом, маршрутом і статусом; коли доступно — також з `user_id`, `error_code` та розміром відповіді.
- У файл записуються лише записи рівня `error`; `info`, `warn`, `debug` і `verbose` ігноруються.
- Web proxy має передавати `trace_id` до API, але не створювати власних файлових логів.
- Логи не мають містити паролі, session token, cookie, повний email, назви чи суми фінансових записів.
- Неочікувана помилка має містити безпечний шлях запиту без query/body, шаблон маршруту, stack trace, первинне місце помилки та першу точку в коді застосунку (`file`, `line`, `column`, `function`).
- Код має бути достатньо простим для подальшої підтримки та розвитку петпроєкту.
